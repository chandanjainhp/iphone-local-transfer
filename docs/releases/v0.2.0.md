# Local iPhone Transfer 0.2.0

A local-only desktop app that copies accessible iPhone photos and videos to a folder
on your computer over a USB cable. No server, no account, no telemetry, no network
transfer of any kind — and nothing on the iPhone is ever deleted or modified.

**Linux x86-64 only.** macOS and Windows are not built, not validated, and not
claimed. Physical-device validation on those platforms is still required before
they can be supported.

```bash
# Debian / Ubuntu
sudo apt install ./Local.iPhone.Transfer_0.2.0_amd64.deb

# Fedora / RHEL
sudo dnf install ./Local.iPhone.Transfer-0.2.0-1.x86_64.rpm

# Any Linux distro (no install step, no root needed)
chmod +x ./Local.iPhone.Transfer_0.2.0_amd64.AppImage
./Local.iPhone.Transfer_0.2.0_amd64.AppImage
```

The `.deb` and `.rpm` depend on your distribution's `libimobiledevice` and `usbmuxd`
packages, so the package manager brings the USB tooling with them. The AppImage
bundles everything it needs and is the largest download.

## What's new

This release is about the interface, the security posture, and the gates that keep
both honest. The copy engine keeps the same non-destructive, non-clobbering
semantics as 0.1.0.

### Added

- **Notification centre** — a local, offline store built from pure functions and a
  reducer: an inline `role="alert"` banner for the newest unread problem, a
  non-modal popover panel, `All` / `Unread` filters with counts taken from the rows
  actually in scope, per-category filtering, collapse of repeated events, dismissal,
  and bounded `localStorage` persistence. Every row comes from an event this app
  genuinely produces; nothing is fabricated, and no file contents or full source
  paths are stored.
- **Icon and design systems** — one semantic icon registry on `@phosphor-icons/react`
  with accessibility enforced by the types, and a single token block for light and
  dark appearance: one interactive accent colour, a documented type ladder, fixed
  radii and spacing steps, and one elevation recipe. No rule hard-codes a colour,
  size, radius or spacing value.
- **Responsive layout** — two documented width tiers (narrower rail and no date
  column below 1024 px; a single column with a wrapping sidebar rail, stacked topbar
  and viewport-anchored notification sheet below 768 px), `auto-fit` stat tiles,
  fluid sizing, `100dvh`, safe-area insets and 44 px touch targets on coarse
  pointers. Page-level horizontal scrolling is gone.
- **Automated gates** — CI runs dependency audits (`cargo audit`, `npm audit`), an
  offline secret scan, `cargo fmt`, `cargo clippy -D warnings`, the full test suite
  and the frontend build on every push and pull request and weekly; an optional
  pre-commit hook runs the secret scan locally.
- **Test suites** — 65 Rust unit tests and 72 frontend tests (63 for the notification
  store, 9 for the responsive-layout invariants).
- **Committed lockfiles** — `package-lock.json` and `src-tauri/Cargo.lock` for
  reproducible builds and reviewable dependency changes.

### Fixed

- **Silent overwrite path removed.** Publishing claims the final name only after the
  temporary file has been flushed and its byte count verified, and on filesystems
  without hard links the name is claimed with an exclusive create — so a file that
  appears in the destination during the copy is never replaced.
- **The webview CSP is enabled.** It was `null`, meaning no content security policy
  at all; it is now `default-src 'self'` with no `unsafe-inline` / `unsafe-eval` and
  no network origins, with a separate development policy for the Vite dev server.
- **Trusted tool discovery.** The `libimobiledevice` binaries are resolved through a
  documented search order and checked for executability, with install hints when
  they are missing.
- **Narrow-window layout defects.** The root `min-width: 760px` that clamped every
  smaller viewport, a device-card copy column that collapsed to one character per
  line, and a stat grid that reflowed unpredictably were all removed or rebuilt.
- **Copy cancel/disconnect reporting** is per item, and the partial file is deleted:
  a partial copy is never presented as a completed one.

### Security

- 0 critical and 0 high findings after remediation; 7 issues fixed during the
  assessment. Full evidence and reasoning: `security-audit-report.md` in the
  repository.
- 0 vulnerabilities in shipped dependencies; no secret material found in the
  repository.
- 2 accepted `cargo audit` warnings, both upstream-only and unreachable from
  application code (`RUSTSEC-2024-0429` `glib` unsoundness with no upgrade path
  inside Tauri's GTK requirement, and `RUSTSEC-2024-0370` `proc-macro-error`,
  build-time only). Reasoning and measurements are recorded in §13.5–§13.6 of the
  report rather than left as a bare ignore list.

## Still true, and still not done

- Source files on the iPhone are never deleted or modified; the app only reads.
- Transfers stay local: no telemetry, no accounts, no cloud, no network requests.
- Only the photos and videos iOS itself exposes over USB are listed. Private app and
  system files are out of scope, and the app says so instead of pretending.
- iOS may expose no files over AFC while iCloud Photos is set to *Optimize iPhone
  Storage* and the phone is locked. The app reports that honestly.
- Resuming an interrupted transfer is not guaranteed; completed files are always
  preserved.
- macOS and Windows remain untested and unpackaged, and there is no automated release
  workflow yet — these artifacts were built and attached by hand.
